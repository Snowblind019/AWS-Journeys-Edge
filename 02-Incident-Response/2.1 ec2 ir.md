# 2.1 — EC2 Incident Response

**Domain 2: Incident Response (14%)**
**Companion to:** `scs-c03-lab-2_1-ec2-incident-response.md` (the runnable lab). This file records what was built and *why each result happens*, one level deeper than the lab's terse `Result:` lines.

**Cost:** about $0. A t3.micro is free-tier eligible and one EBS snapshot is pennies. Do not subscribe to Shield Advanced ($3,000/month, one-year commitment), just read its role, and tear the instance down at the end.

---

## What I built

- Staged a victim EC2 with an instance profile and a **live SSH session** standing in for the attacker's established connection.
- Built the **wrong answers first**: terminating (destroys RAM and the EBS volume), and swapping to a restrictive security group (the SSH session survived, because SGs are stateful and the new SG still allowed all egress).
- Applied the **correct containment**: an empty SG with egress revoked plus a stateless NACL deny, and watched the SSH session drop.
- Prevented **auto-replacement**, **revoked the role's live credentials** by token issue time, and **snapshotted** the volume for clean-room analysis.

The point was that EC2 incident response is an ordered sequence, and the naive answers that "stop the attack" destroy evidence or fail to contain. The whole subdomain is contain without destroying, revoke credentials that outlive the role, preserve in a clean room, and have the break-glass role pre-staged.

---

## The model this proves

EC2 IR is a sequence, and each step has a reason the exam tests directly.

- **Contain without destroying evidence.** Terminating or stopping destroys volatile memory, and terminating destroys the EBS volume if `DeleteOnTermination` is true, so memory forensics has to happen on the running instance first. A security group swap does not contain an active intrusion, because SGs are stateful and connection tracking keeps established flows alive, and a fresh SG still allows all egress. The correct containment is an empty SG with egress revoked plus a stateless NACL deny.
- **Prevent auto-replacement.** Detach from the Auto Scaling group, enable termination protection, and deregister from the load balancer.
- **Revoke live credentials.** The instance metadata handed out temporary STS credentials, and deleting the role does not invalidate already-issued tokens, so you deny by `aws:TokenIssueTime`.
- **Preserve in a clean room.** Snapshot with chain-of-custody tags, share to an isolated forensics account, and analyze a copy, never the live victim.
- **Pre-stage.** The break-glass responder role must exist before the incident.

| Containment action | Kills the live session? | Preserves evidence? | Verdict |
|---|---|---|---|
| Terminate instance | yes, but so does everything | no, RAM and maybe EBS gone | wrong, destroys evidence |
| Stop instance | no | no, RAM gone | wrong for memory forensics |
| Swap to restrictive SG | no, stateful flows survive | yes | insufficient alone |
| Empty SG, revoke egress, stateless NACL deny | yes, NACL evaluates every packet | yes | correct containment |

---

## What each demo proved

**Wrong answer A: terminate destroys the evidence.**
Terminating stops the attack but takes all volatile memory with it, and the EBS volume too if `DeleteOnTermination` is true, which is the default for the root volume. There is no undo. This is why the terminate-first option is always wrong on the exam even though it appears to work. Stopping is also evidence-destroying, because RAM does not survive a stop, so memory forensics must capture from the running instance first (SSM Run Command or a forensic agent).

**Wrong answer B: the SG swap does not contain.**
Moving the instance to a restrictive security group leaves the still-open SSH session connected, because security groups are stateful and connection tracking keeps established flows alive, so removing inbound rules only blocks new connections. And the fresh SG still allows all egress, so the instance can keep exfiltrating outbound until you explicitly revoke egress.

**Correct containment: stateless kills the live session.**
An empty quarantine SG with egress revoked plus a stateless NACL that denies all traffic in and out drops the SSH session immediately, because a NACL evaluates every packet rather than tracking connections. The caveat is that a NACL applies to the whole subnet, so you isolate the compromised instance in a dedicated quarantine subnet, or rely on the empty SG with egress revoked for ENI-level scoping.

**Prevent auto-replacement.**
Detaching from the Auto Scaling group (decrementing desired capacity), enabling termination protection, and deregistering from the load balancer target group stop anything from terminating or replacing the evidence.

**Revoke the live credentials.**
An inline deny scoped by `aws:TokenIssueTime` invalidates all currently-issued temporary credentials without deleting the role, which is what the console "Revoke active sessions" button does via the `AWSRevokeOlderSessions` policy. Because the role still exists, forensics tooling that re-assumes it afterward still works.

**Preserve for clean-room analysis.**
Snapshotting the volume with chain-of-custody tags before touching the disk, then sharing it to an isolated forensics account and attaching a copy to a hardened analysis instance, keeps the investigation off the live victim.

## The subtle one: stateful containment fails, credentials outlive the role, and evidence order

Several tested edges here.

**Stateful containment does not kill a live session.** This is the headline. Security group connection tracking keeps the attacker's established flow alive after a rule change, so an SG swap alone is not containment. A stateless NACL deny is what tears down the live session, because it evaluates every packet. It is the same stateful-versus-stateless distinction from 3.1, now with an incident-response consequence.

**Revoked credentials outlive the role.** Deleting or detaching the role does not invalidate already-issued STS tokens, which stay valid until expiry. The fix is a deny keyed to `aws:TokenIssueTime`, which invalidates every current session while keeping the role for forensics.

**Evidence order is strict.** Memory does not survive a stop, so capture it from the running instance first, and snapshot before touching the disk, since terminating destroys the EBS volume too. The order is contain, capture, preserve, then investigate a copy in a clean room, never the live victim.

**The break-glass role is pre-staged.** Blast radius is minimized at architecture time (account segmentation, least privilege, SCP guardrails, small subnets), not at incident time, and the responder role has to exist before the fire because you cannot build trust during it.

---

## Exam relevance

- **Terminating or stopping a compromised instance destroys volatile memory**, and terminating destroys the EBS volume if `DeleteOnTermination` is true. Capture memory from the running instance before any stop, and treat terminate-first as always wrong.
- **A security group swap does not contain an active intrusion**, because SGs are stateful and keep established flows alive, and a new SG allows all egress. Correct containment is an empty SG with egress revoked plus a stateless NACL deny, ideally in a dedicated quarantine subnet.
- **Prevent auto-replacement:** detach from the ASG, enable termination protection, deregister from the load balancer.
- **Revoke live credentials with a deny on `aws:TokenIssueTime`** (the console "Revoke active sessions" action), which invalidates issued tokens without deleting the role.
- **Preserve with a volume snapshot and chain-of-custody tags**, and analyze a copy in an isolated forensics account, never the live victim.
- **The break-glass IR role must be pre-staged** with MFA-gated trust and least privilege. Blast radius is an architecture-time property, not an incident-time one.
