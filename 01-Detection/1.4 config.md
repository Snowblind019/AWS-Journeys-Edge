## The model this proves

Config records the configuration of your resources over time as configuration items (CIs), evaluates rules against that state, and can remediate. The pieces and their tested edges:

- **The recorder is the foundation.** It emits a CI on every change (continuous) or once a day if changed (daily), and it must record all supported types including global to feed downstream consumers like Security Hub CSPM (the 1.3 dependency) and Firewall Manager (which requires continuous).
- **Rules come in managed and custom flavors**, firing either change-triggered or periodic.
- **Remediation runs an SSM Automation document**, and detection and remediation are two separate permission surfaces.
- **Conformance packs** bundle rules and remediations, and org conformance packs enforce a baseline member accounts cannot weaken.
- **The aggregator is read-only visibility** across accounts and regions, not enforcement.
- **Advanced query** runs SQL over your CIs, which makes Config a Detection and IR data source.

| Rule type | Trigger | When to use |
|---|---|---|
| Managed, change-triggered | a CI change on the resource | most checks, prefer this |
| Managed, periodic | a schedule (1/3/6/12/24h) | checks with no change event, "every N hours regardless" |
| Custom, Lambda-backed | your code per CI | no managed rule fits, need logic |
| Custom, CFN Guard | declarative policy-as-code, no Lambda | no managed rule fits, prefer no code |

| Recording frequency | Cadence | Use for |
|---|---|---|
| Continuous | a CI on every change | real-time security, required by Firewall Manager |
| Daily | one CI per 24h if changed | cheaper, slow-moving or dev |

## What each demo proved

**The recorder: the foundation everything depends on.**
Starting the recorder for all supported types with global types is what feeds every downstream consumer. A narrow recording group leaves controls blind, which is exactly what flipped Security Hub controls between `NOT_AVAILABLE` and evaluated in 1.3. Continuous recording is required for real-time security and for Firewall Manager, so "Firewall Manager is not seeing our resources" is a recorder that is not continuous or not recording that type.

**A managed rule: change-triggered compliance.**
The `restricted-ssh` managed rule evaluates whenever a security group changes, so opening 0.0.0.0/0 on port 22 makes it `NON_COMPLIANT` within minutes. This is the default rule shape.

**Custom rules: only when managed does not fit.**
When no managed rule covers the policy, you write a Lambda-backed rule (your code returns compliance per CI) or a CloudFormation Guard policy-as-code rule (declarative, no Lambda). Managed rules are cheaper to operate and need no code, so custom is the exception.

**Remediation, broken first.**
With an under-permissioned `AutomationAssumeRole`, the rule goes `NON_COMPLIANT`, remediation triggers, and nothing happens, because the SSM automation cannot make the EC2 change. Swapping in a role that allows `ec2:RevokeSecurityGroupIngress` and is trusted by `ssm.amazonaws.com` strips the offending rule automatically. Detection and the fix are two separate permission surfaces.

**Conformance packs: bundle and enforce org-wide.**
A conformance pack is a YAML bundle of rules and remediations deployed as one unit, and an organization conformance pack enforces it across accounts in a way member admins cannot modify, the same tamper-resistance idea as SCPs. Prebuilt packs exist for NIST 800-53, PCI DSS, CIS, and S3 best practices.

**Aggregator: visibility, not enforcement.**
An aggregator gives one read-only dashboard of compliance across accounts and regions, but it fixes nothing. Enforcement is rules plus remediation or conformance packs.

**Advanced query: Config as an IR tool.**
`select-resource-config` runs SQL over your CIs to answer inventory and incident questions, like what resources have a given property or what was created after the breach window, which is Config doubling as a Detection and IR data source.

## The subtle one: two permission surfaces, and visibility versus enforcement

Three tested edges here.

**Remediation has two separate permission surfaces.** The Config rule detects non-compliance, and a distinct SSM `AutomationAssumeRole` performs the fix. When remediation silently does nothing, the cause is almost always that role, missing, untrusted by SSM, or under-permissioned, and the exam loves splitting the two. Start with manual remediation and automate only once tested, because auto-remediation on a misjudged rule can revoke access fleet-wide, which is why "notify or ticket before auto-remediating" is the safe answer.

**Change-triggered versus periodic.** Change-triggered rules fire on a CI change, periodic rules run on a schedule regardless of changes, and some checks are periodic-only because nothing emits a change event. "Evaluate every 12 hours even if nothing changed" is a periodic rule.

**Aggregator is visibility, not enforcement.** "Single dashboard of compliance across the org" is an aggregator, and "make them compliant" is rules and remediation or conformance packs. Watch double billing too: if Security Hub standards and a Config conformance pack check the same thing, you pay for both.

## Exam relevance

- **Config records configuration state as CIs.** The recorder must be continuous and record all supported plus global types to feed Security Hub CSPM and Firewall Manager. "Firewall Manager not seeing resources" or "controls show no data" is a recorder problem.
- **Managed rules are preferred**, and custom rules (Lambda-backed or CFN Guard) only when no managed rule fits.
- **Change-triggered rules fire on change, periodic rules run on a schedule regardless**, and some checks are periodic-only.
- **Remediation runs an SSM Automation document with a separate `AutomationAssumeRole`.** Silent remediation failure is that role (missing, untrusted, under-permissioned). Test manually before automating.
- **Org conformance packs enforce a baseline member accounts cannot weaken**, like SCPs. Avoid duplicating controls with Security Hub to avoid double billing.
- **The aggregator is read-only cross-account and cross-region visibility**, not enforcement.
- **Advanced query (SQL over CIs) makes Config an inventory and IR data source.**
