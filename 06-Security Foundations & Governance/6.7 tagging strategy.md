# 6.7 — Tagging Strategy

**Domain 6: Security Foundations and Governance (14%)**
**Companion to:** `scs-c03-lab-6_7-tagging-strategy.md` (the runnable lab). This file records what was built and *why each result happens*, one level deeper than the lab's terse `Result:` lines.

**Cost:** $0. Tag policies, SCPs, ABAC condition keys, cost allocation tag activation, and Resource Groups are all free. The only thing that bills is whatever resource you tag, so use a free one (an SSM parameter or an existing bucket).

---

## What I built

- Attached a **tag policy** that standardized the `CostCenter` key's value and case, and watched it **fail to stop an untagged instance**, the headline trap.
- Closed that gap with an **SCP** that denies creation when the tag is absent (`Null` on `aws:RequestTag`), and noted the create-then-tag CloudFormation break.
- Built **ABAC** with the `aws:ResourceTag` equals `aws:PrincipalTag` pattern and protected the authorization tag, reinforcing Domain 4.
- Activated **cost allocation tags** and built a **Resource Group** by tag query, for cost, management, and incident response.

The point was that tags are the substrate for access control, cost governance, and incident response, and the exam's hardest split is shape versus presence. A tag policy standardizes what a tag looks like but never forces it to exist, so requiring a tag at creation is an SCP with `aws:RequestTag`. And a tag is only a control when a policy reads it.

---

## The model this proves

Tags underpin access control, cost, and incident response, and the subdomain is a few clean distinctions.

| Control | Governs | What it does |
|---|---|---|
| Tag policy | shape (value, case, allowed values) | blocks noncompliant tag values on supported types, never presence |
| SCP with `aws:RequestTag` `Null` | presence | denies creation when the required tag is absent |

The four condition keys drive everything tags do:

| Condition key | Refers to | Typical use |
|---|---|---|
| `aws:RequestTag/<key>` | a tag value being passed in the request | require or constrain a tag at creation |
| `aws:ResourceTag/<key>` | a tag already on the target resource | allow actions only on resources tagged a certain way |
| `aws:PrincipalTag/<key>` | a tag on the calling user or role | match caller attributes to resource attributes (ABAC) |
| `aws:TagKeys` | the set of tag keys in the request | restrict which keys may be set (`ForAllValues`/`ForAnyValue`) |

A tag is only metadata until a policy references it, so it becomes access control through an IAM policy, SCP, or service condition, and cost governance only when activated as a cost allocation tag.

## What each demo proved

**Tag policy: shape, and the trap.**
A tag policy standardizing the `CostCenter` key blocks a wrong-case `costcenter` tag or a disallowed `CostCenter=Marketing` value on EC2 instances, because `enforced_for` covers `ec2:instance`. But launching an instance with no tags at all succeeds, because an untagged resource has no `CostCenter` tag to evaluate and tag policies only evaluate tags that are present. Tag policies enforce value and case, never presence, and enforcement only works on supported resource types, so it is reporting-only elsewhere.

**SCP: require presence.**
An SCP that denies `ec2:RunInstances` when `aws:RequestTag/CostCenter` is `Null` denies the untagged launch, because `Null` is true when the tag is absent. The SCP forces the tag to exist and the tag policy still governs its value and case, so the two are a pair: SCP requires presence, tag policy standardizes shape. The trap is the create-then-tag break, where a service like Secrets Manager creates then tags in two steps, so the resource exists untagged for a moment and the require-tag SCP blocks it, which is the "my CloudFormation stack fails to create a secret after we added the SCP" symptom. Control Tower controls and Service Catalog launch constraints can also enforce tagging at provisioning, but the SCP with `aws:RequestTag` is the most direct and portable.

**ABAC: tags as access control.**
An identity policy allowing start and stop only when `aws:ResourceTag/project` equals `aws:PrincipalTag/project` lets a principal act on only the resources sharing its project tag, so one rule scales across every project without a new policy per team. This is the 4.6 pattern. You must also deny modifying the `project` tag key (via `aws:TagKeys`), or anyone who can rewrite the authorization tag can grant themselves access to anything, and the model collapses.

**Cost allocation tags and Resource Groups.**
Activating user-defined tags as cost allocation tags in the payer account's Billing console makes spend break down by `CostCenter` or `Environment` in Cost Explorer and the Cost and Usage Report (AWS-generated tags carry the `aws:` prefix). A Resource Group built on a tag query groups resources for bulk management, and keyed on `Environment=prod` or `project=atlas` it turns "act on everything in this blast radius" into a single query during an incident.

## The subtle one: shape versus presence, RequestTag versus ResourceTag, and tags are not security alone

Several tested edges here.

**Tag policy governs shape, SCP governs presence.** A tag policy standardizes value and case on supported types and never forces a tag to exist, so "ensure every instance is created with a CostCenter tag" is an SCP with `aws:RequestTag` and a `Null` condition, not a tag policy.

**RequestTag versus ResourceTag is the most-confused pair.** `aws:RequestTag` is the tag in the API call, existing only during a create or tag operation, and `aws:ResourceTag` is the tag already attached to the thing you are acting on. "Require CostCenter when launching" is RequestTag, "only stop instances tagged Env=prod" is ResourceTag.

**The create-then-tag CloudFormation break.** A deny-based require-tag SCP blocks services that create then tag in two steps (Secrets Manager), so test deny-based tag SCPs against your services and IaC before rolling them org-wide.

**ABAC collapses if the authorization tag is editable.** Always pair an ABAC allow with a deny on modifying the auth tag key via `aws:TagKeys`, the follow-up people forget.

**Tags are not security by themselves.** A tag is metadata that becomes a control only when a policy, SCP, or service reads it in a condition, so tagging buckets `Confidential` does nothing until a policy restricts on `aws:ResourceTag/Classification`.

## Exam relevance

- **Tag policy governs shape (value, case, allowed values on supported types), an SCP with `aws:RequestTag` and a `Null` condition governs presence.** A tag policy alone cannot require a tag to exist.
- **The four condition keys:** `aws:RequestTag` (in the request), `aws:ResourceTag` (already on the resource), `aws:PrincipalTag` (on the caller, ABAC), `aws:TagKeys` (which keys, with `ForAllValues`/`ForAnyValue`). RequestTag versus ResourceTag is the most-confused pair.
- **Deny-based require-tag SCPs break create-then-tag services like Secrets Manager**, so test against your IaC. Control Tower controls and Service Catalog launch constraints can also enforce tagging, but the SCP is most portable.
- **ABAC scales access by tags** (`aws:PrincipalTag` matched to `aws:ResourceTag`), and you must deny editing the authorization tag key (`aws:TagKeys`) or the model collapses. ABAC is the self-scaling answer, RBAC is the fixed-job-functions answer.
- **Cost allocation tags activated in the payer account surface spend by tag** in Cost Explorer and the CUR, and `aws:` prefix tags are AWS-generated.
- **Resource Groups group by tag query for bulk management and one-query incident response**, which depends on a consistent tagging scheme applied ahead of time.
- **A tag is not security by itself.** The control is the policy that reads the tag.
