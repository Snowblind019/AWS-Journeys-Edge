# 3.3 — VPC Connectivity (IGW/NAT, Peering, Transit Gateway)

**Domain 3: Infrastructure Security (18%)**
**Companion to:** `scs-c03-lab-3_3-vpc-connectivity.md` (the runnable lab). This file records what was built and *why each result happens*, one level deeper than the lab's terse `Result:` lines.

**Cost:** watch this one. NAT gateway and Transit Gateway both bill hourly plus per-GB, the EIP bills hourly, and peering connections are free. Delete the NAT and TGW first, then release the EIP, or the order leaves the EIP billable.

---

## What I built

- Proved a subnet is "public" only because its route table points `0.0.0.0/0` at an **internet gateway**, and a private subnet with no such route cannot reach the internet at all.
- Added a **NAT gateway** in the public subnet so the private instance gets outbound internet, and confirmed nothing outside can initiate a connection to it.
- Built a peering chain A to B to C, then proved **A cannot reach C through B** because peering is non-transitive, and fixed it with a direct A to C peering.
- Stood up a **Transit Gateway** as the hub that replaces the mesh.

The point was that internet reachability is a route, not a setting, and connecting many VPCs is a choice between non-transitive peering (fine for a few) and a transitive Transit Gateway hub (the scale answer), with segmentation being a route-table design problem in both.

---

## The model this proves

**Part 1, what makes a subnet public.** There is no public-subnet toggle in AWS. A subnet is public only if its route table has a route to an internet gateway. Auto-assign-public-IP only hands the instance an address, and without the IGW route that address is useless. Three gateways cover the directions:

| Gateway | Direction | IP version | Purpose |
|---|---|---|---|
| Internet gateway (IGW) | bidirectional | IPv4 and IPv6 | makes a subnet public |
| NAT gateway | outbound only | IPv4 only | private instances reach the internet, no inbound |
| Egress-only IGW | outbound only | IPv6 only | the IPv6 equivalent of NAT |

**Part 2, connecting VPCs.** Peering is one-to-one and non-transitive, and a Transit Gateway is a transitive hub:

| Property | VPC peering | Transit Gateway |
|---|---|---|
| Topology | one-to-one mesh | hub-and-spoke |
| Transitive | no | yes, subject to TGW route tables |
| Scaling | n(n-1)/2 connections | one attachment per VPC |
| Reaches on-prem (VPN/DX) | no | yes |
| Cross-region | yes, via peering | yes, via TGW peering |
| Cost | free | hourly plus per-GB |
| Overlapping CIDRs | forbidden | forbidden |

## What each demo proved

**Public subnet: the IGW route is the only thing that matters.**
The route to the IGW is what makes the subnet public. A private subnet with no such route cannot reach the internet, which a hanging `dnf update` confirms. The public IP alone does nothing without the route.

**NAT gateway: outbound only, and placement matters.**
Adding a NAT gateway in the public subnet and routing the private subnet's default through it lets the private instance reach the internet, while nothing outside can initiate a connection to it, because NAT only handles the return path of connections the instance started. The NAT must live in the **public** subnet, since it needs the IGW route to reach the internet, and the private subnet routes to the NAT. Putting the NAT in the private subnet is a common broken build.

**Peering: non-transitive, proven by A to C failing.**
A reaches B and B reaches C, but A to C fails with 100 percent loss even after adding a route in A that points at the A to B peering. B will not forward A's traffic onward, and peering explicitly forbids edge-to-edge routing, so you cannot route through a peer to reach that peer's other peerings, IGW, NAT, VPN, or endpoints. The fix is a direct A to C peering. Peering also forbids overlapping CIDRs and requires route-table edits on both sides, and a one-sided route is the silent-failure version of this lab.

**Transit Gateway: the scale answer.**
Three VPCs need three peerings, twelve need 66 (n(n-1)/2), and that mesh is what TGW solves by attaching each VPC once to a central hub. TGW is transitive (subject to its route tables), connects on-prem over VPN or Direct Connect, and peers across Regions.

## The subtle one: transitivity boundaries and default-open assumptions

Several sharp edges here, and two of them are mirror images.

**Peering is non-transitive and forbids edge-to-edge routing.** You cannot borrow a peer's internet, NAT, VPN, or endpoints, and you cannot hop through a peer to a third VPC. If a design needs any-to-any connectivity at scale, peering is the wrong tool.

**TGW is transitive but not open by default.** Segmentation is enforced by which attachments associate to and propagate into which TGW route table. "We attached everything and prod can see dev" is a route-table design failure, not a TGW limitation. This is the mirror of the peering trap: peering is too closed to be transitive, while TGW is transitive but only as open as you configure it.

**NAT is IPv4 only.** For IPv6 outbound-only you need an egress-only internet gateway, and a NAT gateway will not do it. This IPv4-versus-IPv6 swap is a frequent exam trap.

**Public IPv4 is no longer free.** Since February 2024 AWS bills every public IPv4 address at roughly $0.005/hour even when attached, on top of NAT's own hourly and per-GB charges, which changes the cost math on "just give it a public IP."

## Exam relevance

- **A subnet is public only because of a route to an IGW**, not a toggle and not the public IP.
- **IGW is bidirectional, NAT gateway is outbound-only IPv4, egress-only IGW is outbound-only IPv6.** The IPv6 swap is a common trap.
- **NAT gateway lives in the public subnet**, and the private subnet routes to it. NAT in the private subnet is a broken build.
- **VPC peering is one-to-one, non-transitive, no edge-to-edge routing, no overlapping CIDRs, routes on both sides.** It scales as n(n-1)/2.
- **Transit Gateway is the transitive hub** for many VPCs, reaches on-prem over VPN and Direct Connect, and peers across Regions. Segmentation is a route-table design, and it is not open by default.
- **Public IPv4 addresses bill hourly since Feb 2024**, and NAT and TGW bill hourly plus per-GB while peering is free. Delete NAT and TGW before releasing the EIP.
